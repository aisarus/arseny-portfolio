Aegis Operator

What if the AI worker was not the system, but one worker inside a system with contracts, limits, evidence and owner control?

Architecture

GOAL → CONTRACT → PLAN → EXECUTION → FAILURE → REPLAN → VERIFIED

Aegis turns an ambiguous goal into an acceptance contract and strategy, decomposes it into jobs, routes work to specialized text/coding workers, gathers evidence and decides whether work should be accepted, rejected or replanned. The public source is a curated runnable snapshot intended to make the architecture and regression coverage inspectable.

Why it matters

The project is built around a simple rule: a model saying “done” is not enough. Checkable facts, limits and acceptance conditions stay deterministic where practical. Interesting engineering work came from failures: state-observation side effects that broke loop recognition, a lifecycle-ordering bug initially mistaken for provider quota, and stale budget reservations after crashed processes.

My role

Product concept, architecture and constraints, decomposition, agent direction, review, failure diagnosis, verification design and iteration. Substantial implementation code was produced with coding agents; that is part of the development method rather than hidden authorship.
