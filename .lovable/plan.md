# Homepage V3: Broadcast Signal System

## Goal
Rebuild the entire homepage as one authored corrupted-broadcast-to-clean-signal experience while preserving all verified public copy, keeping `/cv` unchanged, and retaining the noindexed concept routes.

## What will change
- Add a reusable section-level signal layer with deterministic TV tears, RGB fringe, scanlines, snow, vertical roll, blur instability, and broad degauss-style cursor/touch clearing.
- Make clearing fast and wide on desktop, persistent for several seconds, automatic around the reading region on mobile, and fully disabled under reduced motion.
- Recompose every homepage section around a distinct interaction:
  - Hero: aggressive corrupted broadcast with hidden stabilized keywords.
  - Operating Model: magnetic waveform/tracking strip with keyboard-accessible lock-on stages.
  - Aegis: shard reassembly, inspectable architecture nodes, failure notes, and a scrubbed run-flow lane.
  - Failure Index: forensic CCTV/oscilloscope incidents with distinct corruption signatures and ghost diagnoses.
  - Lamdan: quieter scanned-document recovery with interactive provenance stages.
  - BotForge: front-surface/back-system X-ray lens plus explicit security state.
  - Lab: four asymmetric, larger interaction toys with distinct behavior and inspectable operational states.
  - About and Contact: progressively calmer signal, ending fully locked and crisp.
- Keep semantic copy readable beneath visual layers; all duplicate glitch text will be decorative and hidden from assistive technology.

## Technical approach
- Build one shared React signal primitive using pointer refs, IntersectionObserver, CSS custom properties, deterministic seeded geometry, and requestAnimationFrame only while visible.
- Use CSS/SVG/canvas selectively; no new heavy dependency, no scroll hijacking, and no fixed-width layouts.
- Keep interactions as progressive enhancement so keyboard, touch, SSR, and reduced-motion states remain complete.
- Do not edit `src/routes/cv.tsx`; verify its hash before and after.

## Verification
- Run TypeScript and production build checks.
- Exercise all interactions with Playwright at 1440×900 and 375×812, plus a reduced-motion pass.
- Assert no horizontal overflow, console errors, or page errors.
- Capture and inspect Hero, Operating Model, Aegis, Failures, Lamdan, BotForge, Lab, Contact, plus mobile Hero/Aegis/Lab screenshots; correct clipping, overlap, unreadable noise, or weak section differentiation before completion.
